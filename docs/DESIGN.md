# Desktop design

**Platform:** Ubuntu/Linux, Qt 6 Widgets. **Audience:** engineers inspecting serial MAVLink traffic.

**Direction selected by the user:** Modern dashboard, clearly separated regions, more breathing room and moderately larger typography. The **ui-ux-pro-max** search `modern operational dashboard spacious` returned an unsuitable landing-page structure; the focused style search `minimalism swiss dashboard` verified the **Minimalism & Swiss Style** profile. Its spacing, hierarchy, contrast and restrained accent guidance fits this desktop. Qt is not a supported stack in the dataset, so the actual native layout uses desktop design judgment rather than web/mobile framework rules.

- **Hierarchy:** native menu bar (File, View, Tool, Help), a standalone app title on the left and a compact background-free UART group aligned to the right of the same header row, two-column workspace, status bar. **TX Dashboard** occupies a resizable left column; **RX Dashboard** occupies the larger right column. RX streams and decoded fields use a vertical splitter, keeping complete rows readable at the minimum window size. UART settings open in a popup without changing workspace geometry.
- **UART configuration:** a compact, background-free group stays at the right edge of the header. The 160 px editable Port and 32 px Refresh icon form a close pair (4 px gap); Baud is separated by 12 px, followed by a 32 px Settings sliders icon and the primary Connect/Disconnect action. All input/action controls are 32 px tall. Connection state is reflected by the Connect/Disconnect action; there is no separate UART status label or LED. Port filtering and typed device/PTY paths are retained.
- **UART settings popup:** the Settings icon has an accessible name and `UART settings` tooltip. The popup uses a translucent window with a rounded mask (7 px radius) refreshed on Show/Resize, and owns one continuous background and outer border; the embedded settings frame is transparent with no inset border. A compact two-column popup below the icon contains the framing/flow summary and labeled Data bits, Parity, Stop bits and Flow control inputs. Values remain unchanged when dismissed; configuration is disabled while connected. Escape or clicking outside dismisses the popup. Popup opening does not resize the header or move the dashboards. Position is bounded horizontally by the application window. The layout follows Qt desktop judgment; the focused skill search verified async-action loading guidance but did not return a matching desktop toolbar grouping rule.
- **Spacing:** 20 px outer horizontal margins, 16 px panel padding, 8 px header/dashboard gap and 12 px TX/RX gap, 12 px internal rhythm; resizable dashboard and inspector splitters.
- **Typography:** platform sans-serif, 22 px app title, 18 px panel titles, 14 px controls, 15 px TX message names and 12 px supporting text. System fixed-pitch font for decoded identifiers and values. No network font dependency.
- **Light:** background `#edf1f8`, surface `#ffffff`, text `#20263b`, secondary text `#626c84`.
- **Dark:** background `#0d1422`, surface `#1b2333`, text `#edf0fa`, secondary text `#aab4cd`.
- **TX creation:** saving a new message while connected requests periodic TX through the worker's existing capacity validation. Adding while disconnected leaves it stopped; connecting/reconnecting does not start it. Editing still stops the saved entry.
- **Actions:** indigo `#4f46e5` Connect/Add and red Stop all text. When connected, Disconnect switches to a quiet outlined action to distinguish it from the primary Connect state. Add stays in the title row; the summary contains only message/running counts. A bottom row groups Run all, Stop all and Delete all. Run all validates the complete load before activation; Delete all stops TX, cancels pending output and clears every TX entry. Run/Stop require a connection and entries; Delete requires entries. Right-clicking a card selects it and opens a menu with Send once, a state-dependent Start/Stop action, Edit message… and Remove message. Empty list areas do not open this menu; keyboard context requests use the current card. TX commands are disabled while disconnected; Edit/Remove remain available for a selected entry. Secondary actions have quiet outlined surfaces. Summaries report configured/running TX entries and displayed RX stream count.
- **TX width:** the initial TX column is 360 px with a 340 px minimum; the splitter remains adjustable. Card content uses 12 px horizontal padding.
- **TX cards:** a single delegate paints each 114 px row as a compact card: 13 px `[ID] MESSAGE_NAME` and state at the top, `System ID: … - Component ID: …` on a secondary line aligned with the title's left edge, and three aligned metrics below: muted Target/Actual/Frames labels above larger values. An interactive inline toggle button with play/stop icons sits directly on the status badge, allowing immediate stream start/stop on click with pointing cursor feedback. Actual transmission rate is highlighted when active. No per-entry widget allocation or transport changes. Running cards use a soft teal surface and teal outline; Stopped cards use a soft gray surface. Error cards use a soft red surface and outline. Cards have no vertical side accent. Status text and play/stop icons remain visible, so color is not the only signal. Selection uses an indigo outline without replacing the state surface; hover, click, keyboard navigation and double-click editing remain available. TX cards have no hover tooltip; full identity/state remains available through accessible text, including elided names and errors.
- **Data hierarchy:** RX streams and decoded fields each have a bordered frame and a dedicated title bar, with distinct header/body surfaces. Light title bars use `#eef2f9` with `#40536e` text; Dark uses `#202d42` with `#d6dfee` text. Data borders are `#d1dbea` / `#35445d`. Tones and selection are intentionally softer than the initial information-separation revision. Splitter gaps remain draggable without hover highlighting. The TX/RX splitter is 12 px wide. TX cards use state-specific soft outlines without a vertical side accent, with a thin separator below the sender line, a left-aligned sender line, and 11 px labels above 13 px metric values. The TX list sits directly on the dashboard panel surface without an inset background, separated from the upper action controls by a subtle horizontal divider. The status bar shows debug metrics in muted 12 px type on the main window background, with dynamic alert colors (red/amber) when CRC errors, queue backpressure or RX overflow are detected.
- **RX tables:** compact rows with 5 px vertical padding, muted System/Component labels, no cell grid, right-aligned numeric headers/values (ID, Count, Hz) with monospace system font, subtle row dividers and stronger selection. Stream activity uses a theme-aware vector LED indicator (green for fresh, amber for aging, muted for stale). Decoded and editable values use a shared delegate for regular blue-gray text (`#3f628b` / `#b2c8e2`), preserving native selection and editing. Changed field values are temporarily highlighted, and common protocol constants (such as HEARTBEAT autopilot/type/status enums) offer human-readable descriptions in tooltips.
- **Inspector:** explicit RECEIVED MESSAGES and DECODED FIELDS title bars; the latter shows the selected message name, ID, System and Component. Right-click a field row and choose Copy value to copy its displayed value; a snapshot is captured when the menu opens. The unavailable unit column is hidden; its limitation remains in the inspector tooltip and documentation.
- **Empty states:** TX, RX and decoded-field viewports remain blank when no data is available, including filter results. No placeholder or guidance overlays are displayed. Panel titles, table headers and actions remain available.
- **Message editor:** a resizable two-column splitter gives the catalog approximately 29% of the default content width. Catalog IDs and names use aligned columns, soft theme-aware selection and keyboard focus; the search field has a vector magnifier and a native clear action. Results rank exact ID/name matches before prefixes and substrings, then numeric ID, while preserving the current message. The selected-message heading sits above 34 px controls; extra spacing separates sender IDs from Protocol/Rate. The parameter table retains its 36 px header, 40 px rows and subtle separators, with 13 px parameter/value and 12 px type text. Value input outlines are quiet at rest and emphasized on hover/focus/error. Read-only constants remain labeled plain values. Validation runs when an edited value commits; an invalid row expands to show its reason below the input and retains its text until corrected. Submit still validates the complete payload and reveals any filtered-out invalid field. Messages with more than 12 fields expose a parameter-name filter. Selecting an array shows contextual guidance and an Edit array action opening a themed multiline editor; Apply uses the existing codec validation, Cancel leaves the value unchanged, and numeric multiline input is compacted for table display. Raw payload drafts, including invalid values and active edits, survive message switching within this dialog only. The fixed footer aligns Cancel followed by the primary action at the right edge: Add & start online, Add message offline, Save changes when editing. Generated metadata does not supply units or enum descriptions, so none are inferred.

- **Interaction:** indigo keyboard focus/selection, stable button bounds, native keyboard traversal, native editable controls, explicit disabled states. Icons, dropdown chevrons and numeric steppers use local theme-aware QPainter vectors; native interactions are retained. No animations, external assets or new dependencies.
- **Status:** text labels distinguish connected/disconnected/error, running/stopped, recent/stale and paused display; meaning does not depend on color.
- **About:** displays the CMake project version, application purpose, key TX/RX features, supported MAVLink versions/dialect and desktop stack.
- **Dialog title bars:** Settings, About and the message editor use application-painted title bars, matching Light/Dark immediately, including when a dialog is already open. Dialogs use a single continuous background, with a thin 1 px divider beneath the title bar inset to the content margins. One 18 px semibold title replaces duplicate body headings. Title and body share a 20 px left inset; a 1 px outer inset keeps the window border continuous. The close button is transparent at rest, with hover/pressed and keyboard-focus feedback. A close button and Escape dismiss dialogs; dragging uses Qt system movement where supported, with pointer movement as a fallback. A size grip preserves resizing. Desktop window-manager title-bar colors are no longer used for these dialogs.
- **Menu Bar & Settings:** The top menu bar provides traditional desktop application access via **File** (Exit), **View** (Pause Display, Clear Messages), **Tool** (Settings...), and **Help** (About). The **Settings** action opens a modal Application Settings dialog organized into styled cards, starting with **Appearance** where users can switch between System, Light, and Dark themes. System theme follows Qt's application palette; explicit Light/Dark overrides are available. System detection depends on the desktop platform theme supplied to Qt.
- **Data stability:** RX rows update in place. The GUI requests at most one outstanding snapshot and refreshes at 5 Hz. Serial processing continues independently.

**Desktop minimum:** 1000 × 720. This is not a mobile interface.

**Information separation refinement:** the focused `surface separation contrast hierarchy` UX search verified Contrast Readability guidance for all platforms: use readable foregrounds and avoid gray-on-gray information. The returned web breadcrumbs guidance was unrelated and was not applied. Frames, tonal layers and label/value emphasis above follow desktop design judgment within the accepted Modern dashboard layout.

**Button focus:** pointer clicks use hover/pressed feedback without an extra focus outline. Tab/Backtab/shortcut focus or Space/Enter input enables one explicit focus border. Buttons retain native keyboard activation and focusability; border/padding changes preserve their overall bounds. The focused skill search `keyboard focus mouse button` verified Focus States guidance: keep a visible keyboard indicator instead of removing focus feedback globally.

**Reduced secondary copy:** the app subtitle, dialect badge and TX/RX footer descriptions are omitted. RX message tooltips retain signature status; blank view areas have no tooltip. Empty-state guidance is omitted; Pause/Resume button feedback remains visible. The focused `text contrast dark mode` UX search verified all-platform readability guidance; status text uses the muted theme foreground on the main background.

**Workspace spacing:** the header has a 10 px top inset, a 40 px control area and an 8 px gap before the TX/RX cards; the app title has no enclosing card or background and its text aligns with the outer left edge of the TX Dashboard card; the UART group has no enclosing background or border and is aligned to the right, with a maximum width of 700 px. Shared serial field labels use 12 px type, while the compact framing summary remains 11 px.

**Developer documentation:** [Architecture](ARCHITECTURE.md), [API contracts](API.md), [Troubleshooting](TROUBLESHOOTING.md). This document describes the current checkout; names/layout from other branches are not implied.

**RX readability refinement:** System/Component labels use muted 12 px text; message names use primary 13 px sans-serif, with numeric columns retaining fixed-pitch alignment. Nested section/header surfaces are quieter. Decoded fields use 13 px names/values and 12 px type annotations with consistent separators and soft row selection. The inspector heading separates `[ID] NAME` from `System … · Component …` on a secondary line. Search uses the same theme-aware vector glyph and native clear action as the message editor; filtered summaries report matching/total displayed streams. Display paused is an explicit label beside the inspector and does not stop parser/counters.

**Long TX names:** headings wrap into at most two lines at the available card width; the second line elides if necessary. Wrapped cards grow from 114 to 130 px, moving sender/divider/metrics down together. Inline status button geometry remains stable. Row heights are recalculated on width/model changes while retaining scroll position.

**Presentation preferences:** a normal close stores window geometry, dashboard/RX splitter states and RX/field header states in application-scoped QSettings (`MAVLinkSimulator/Layout`, schema version 1). Startup restores presentation only, keeping the unavailable Unit column hidden. Invalid geometry/splitter state falls back to the existing usable layout. Serial connection, payloads, TX activation and pause/filter state remain session-only. Multiple instances use the last saved layout. Automated tests redirect settings to a temporary directory.
